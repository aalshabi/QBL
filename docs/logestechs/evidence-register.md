# سجل أدلة التدقيق

آخر تحديث: 2026-08-17
سياسة البيانات: لا تُسجل أسماء العملاء أو هواتفهم أو عناوينهم أو Tokens أو Cookies أو Credentials.

## سلم جودة الدليل

- A: سلوك تم اختباره فعليًا بصورة آمنة.
- B: دليل مباشر ظاهر في الواجهة.
- C: إعداد ظاهر داخل النظام.
- D: دليل API أو Network غير حساس.
- E: توثيق رسمي.
- F: تقرير أو خط أساس داخلي سابق.
- G: استنتاج منطقي فقط.

## أدلة LogesTechs

### LT-R-001 — طلب معلومات التكامل من المورد

- التاريخ المسجل: 2026-08-16.
- المصدر: إفادة المستخدم بإرسال رسالة إلى فريق LogesTechs.
- المطلوب: API documentation، Sandbox، Authentication، Shipment/Driver/Vehicle APIs، assignment APIs، Webhooks، signature verification، rate limits، retry policy، وimport/export formats.
- نوع السجل: Request pending؛ ليس دليل Capability.
- الحالة: رد المورد جزئيًا وأرسل وثيقتي API وWebhook، وطلب حساب عميل مخصصًا للتكامل مع Company ID. ما زالت Sandbox وبقية APIs والضوابط الأمنية غير مجابة.
- قاعدة التقييم: لا تتحول أي نقطة مطلوبة إلى «موجودة» قبل استلام وثيقة رسمية أو اختبار آمن في Sandbox.

### LT-E-012 — وثيقة LogesTechs API v2

- التاريخ: 2026-08-16.
- المصدر: `LogesTechs_API_Documentation (2).pdf`، 14 صفحة، مراجعة نصية وبصرية كاملة.
- نوع الدليل: E.
- الملاحظة: توثق Base URL و`company-id` header وإنشاء الشحنة والمدن والإلغاء وطباعة AWB وحالة شحنة مفردة. إنشاء/إلغاء الشحنة يستخدمان بريد العميل وكلمة المرور.
- النتيجة: REST API موجود لكنه محدود مقارنة بتدفق QBL المطلوب، ونموذج المصادقة يحتاج حساب تكامل وضوابط أسرار قوية.
- الثقة: مرتفعة لما هو موثق.

### LT-E-013 — وثيقة Webhook Status

- التاريخ: 2026-08-16.
- المصدر: `Webhook Status .pdf`، 7 صفحات، مراجعة نصية وبصرية كاملة.
- نوع الدليل: E.
- الملاحظة: توثق Webhooks لحالات Last-mile وFulfillment، وPayload يحمل معرفات الشحنة والحالة والوقت وCOD والمرجع والملاحظات والتأجيل، وقد يحمل بيانات سائق ومرفقات.
- النتيجة: Status Webhooks مثبتة توثيقيًا، لكن التوقيع وEvent ID وRetry وOrdering وReplay protection غير موثقة.
- الثقة: مرتفعة للحقول والحالات، منخفضة للضوابط الأمنية والتشغيلية.

### LT-E-014 — إنشاء حساب عميل للتكامل

- التاريخ: 2026-08-16.
- النظام: LogesTechs Admin Pro.
- المسار: إدارة المستخدمين > العملاء > إضافة زبون.
- نوع الدليل: A.
- الملاحظة: أُدخلت البيانات يدويًا، اختير الفرع الوحيد المتاح، ثم أعاد النظام رسالة نجاح إنشاء العميل.
- النتيجة: حساب تكامل مخصص موجود وجاهز لاختبار المصادقة بعد اعتماد طريقة حفظ السر.
- الخصوصية: لا بريد أو كلمة مرور أو هاتف أو عنوان محفوظ في هذا السجل.
- الثقة: مرتفعة.

### LT-E-015 — اختبار اتصال API للقراءة فقط

- التاريخ: 2026-08-17.
- العملية: `GET /addresses/cities?returnAll=true` مع ترويسة `company-id`.
- نوع الدليل: A.
- الملاحظة: أعادت الخدمة HTTP 200 واستجابة JSON، دون إرسال البريد أو كلمة المرور ودون تسجيل سجلات المدن أو أي PII.
- النتيجة: Base URL والترويسة واتصال API مثبتة عمليًا للقراءة. لا يثبت هذا توفر Shipment list أو Drivers/Vehicles أو Assignment APIs.
- الخصوصية: لم تُطبع أو تُحفظ بيانات الدخول أو محتوى السجلات.
- الثقة: مرتفعة لعملية قراءة المدن فقط.
